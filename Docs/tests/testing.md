# ShiftBot テスト方針・テスト項目

## テストの分類

| 分類 | 対象 | 実施方法 |
|---|---|---|
| 単体テスト | AI判定、ルーティング、データ処理 | pytestで自動実行 |
| 連携テスト | handlerとspreadsheetの連携 | モック・テスト用データを利用 |
| 実運用テスト | LINE、Google Sheets、ユーザー権限 | 手動で確認 |

## テスト項目

### 1 AI判定（ai_parser）

- [ ] 正常なシフト入力を判定できる
- [ ] シフト変更を判定できる
- [ ] 欠勤・遅刻を正しく判定できる
- [ ] 曖昧な入力をunknownなど適切な形式で返す
- [ ] APIエラー時に適切に処理できる

### 2 ルーティング（dispatcher）

- [ ] typeに応じて正しいhandlerを呼び出す
- [ ] 未対応のtypeを適切に処理する
- [ ] handlerのエラーを適切に扱う

### 3 スプレッドシート（spreadsheet）

- [ ] 既存の月別Spreadsheetを取得できる
- [ ] シフトを正しいスタッフ・日付のセルに登録できる
- [ ] 新規登録と更新を区別できる
- [ ] 欠勤・遅刻・変更・希望を正しく記録できる
- [ ] 不存在の月別Spreadsheetを適切に処理する
- [ ] 既存データを不必要に上書きしない

### 4 LINE連携（app）

- [ ] Webhookからメッセージを受信できる
- [ ] 処理結果に応じた返信を送信できる
- [ ] 初回ユーザーを登録できる
- [ ] 重複登録を防止できる
- [ ] スタッフ状態に応じて利用を制限できる

## テストルール

- 自動テストは原則としてpytestで実行する．
- 外部APIを呼び出すテストと，モックを使うテストを区別する．
- 実運用テストではテスト用ユーザー・テスト用Spreadsheetを使用する．
- テスト結果と不具合は `test-results.md` に記録する．
- 未実施の項目を合格扱いにしない．
