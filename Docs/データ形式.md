# データ形式

## 1. シフト登録（shift）

### データ例

```json
{
  "type": "shift",
  "action": "write",
  "date": "2026-06-10",
  "start_time": "18:00",
  "end_time": "22:00",
  "memo": "",
  "ambiguity": []
}
```

### AI入力例

入力：

```text
6/10 18-22
```

出力例：

```json
{
  "type": "shift",
  "action": "write",
  "date": {
    "kind": "md",
    "month": 6,
    "day": 10
  },
  "start_time": "18:00",
  "end_time": "22:00",
  "memo": "",
  "ambiguity": []
}
```

※AI出力では日付情報を構造化して返し、`date_resolver.py` で実際の日付に変換する。

※ `user_id` とスタッフ名は、原則としてAI出力に含めず、LINEのユーザー情報とスタッフ管理シートから取得する。

※終了時刻が未指定の場合は `end_time: null` とする。

---

## 2. シフト変更（shift）

### AI入力例

入力：

```text
10日は20時からです
```

出力例：

```json
{
  "type": "shift",
  "action": "change",
  "date": {
    "kind": "day",
    "day": 10
  },
  "new_start_time": "20:00",
  "ambiguity": []
}
```

変更時に指定する項目：

| キー | 意味 |
|---|---|
| `old_start_time` | 変更前の開始時刻 |
| `old_end_time` | 変更前の終了時刻 |
| `new_start_time` | 変更後の開始時刻 |
| `new_end_time` | 変更後の終了時刻 |
| `memo` | 変更後のシフトに関するメモ |
| `reason` | 変更申請の理由 |

※変更対象の既存シフトは `get_shift()` で取得する。

※変更後の時刻について、指定されていないキーは省略する。省略された項目は既存の値を維持する。

※値が `null` の場合は、その時刻を未定にする。

※変更申請は `write_change()` でSpreadsheetに記録する。現時点では、申請の記録と実際のシフト表への反映は別の処理として扱う。

---

## 3. 自由記述を含むシフト登録（shift）

入力：

```text
10日は19時以降ならいつでも大丈夫です
```

出力例：

```json
{
  "type": "shift",
  "action": "write",
  "date": {
    "kind": "day",
    "day": 10
  },
  "start_time": "19:00",
  "end_time": null,
  "memo": "19時以降ならいつでも",
  "ambiguity": []
}
```

※ `end_time` が `null` の場合は終了時刻未指定として扱う。

※ `write_schedule()` では、終了時刻が未指定の場合は「未定」としてシフト表に表示する。

※確定シフトに登録する際の扱いは、今後の運用ルールに従う。

---

## 4. 遅刻連絡（late）

入力：

```text
15分ほど遅れます
```

出力例：

```json
{
  "type": "late",
  "action": "write",
  "date": null,
  "mode": "delay",
  "delay_minutes": 15,
  "arrival_time": null,
  "reason": "",
  "ambiguity": []
}
```

※ `late_handler.py` では `mode`、`date`、`arrival_time`、`delay_minutes`、`reason` を扱う。

※ `mode` は遅刻の伝え方を表す。`delay` は遅れる時間を指定する形式、`arrival_time` は到着予定時刻を指定する形式。

※日付が省略された場合は `date: null` のまま扱い、自動的に今日の日付を補完しない。

---

## 5. 欠勤連絡（absence）

入力：

```text
体調不良のため休みます
```

出力例：

```json
{
  "type": "absence",
  "action": "write",
  "date": null,
  "reason": "体調不良",
  "ambiguity": []
}
```

※日付が省略された場合は `date: null` のまま扱う。

※元のLINEメッセージと受信日時を記録し、対象日と受信日時を区別する。

---

## 6. AIが判定できなかった場合（other）

入力：

```text
来週金曜遅めから
```

出力例：

```json
{
  "type": "other",
  "action": null,
  "message": "開始時間が特定できません"
}
```

AIが意図や必要な情報を特定できない場合は、推測で補わず確認を求める。

---

## 7. 固定シフト希望（preference）

入力：

```text
毎週火曜日は18時以降なら入れます
```

出力例：

```json
{
  "type": "preference",
  "action": "write",
  "weekday": "Tuesday",
  "start_time": "18:00",
  "end_time": null,
  "available": true,
  "content": "18時以降なら入れます",
  "ambiguity": []
}
```

固定曜日や勤務可能時間などの条件を登録する。

※時刻キーはシフト登録と同様に `start_time` / `end_time` に統一する。

---

## 8. 共通ルール

- `type` は `dispatcher.py` の `HANDLERS` に登録された名称に統一する。
- `action` は `EXPECTED_ACTION` に定義された処理内容に合わせる。

| type | action |
|---|---|
| shift | write / change |
| absence | write |
| late | write |
| preference | write |
| memo | write |
| question | read |
| other | null |

- 日付情報はAI解析時に構造化し、`date_resolver.py` で `YYYY-MM-DD` 形式に変換する。
- `kind: "md"` は月日を指定する形式とする。
- `kind: "day"` は現行の `date_resolver.py` では翌月の日付として解決する。
- 年が省略された場合、過去の日付なら翌年として解決する。
- 日付を特定できないタスクは確認を求め、Spreadsheetへ書き込まない。
- 時刻は `HH:MM` 形式とする。
- AIが判定できない情報は推測で補わず、確認メッセージで対応する。
- `user_id` とスタッフ名は、LINEの送信者情報・スタッフ管理シートを基に補完する。
- 欠勤・遅刻で日付が省略された場合は `null` のまま扱う。
- 既存シフトの変更では、指定されていない項目を上書きしない。
- 変更申請の `memo` と `reason` は別々の項目として管理する。
