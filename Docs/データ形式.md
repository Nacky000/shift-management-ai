# データ形式

## 1. シフト登録（shift）

### データ例

```json
{
  "type": "shift",
  "action": "write",
  "date": "2026-06-10",
  "start_time": "18:00",
  "end_time": "22:00",
  "memo": ""
}
```

### AI入力例

入力：

```text
6/10 18-22
```

出力例：

```json
{
  "type": "shift",
  "action": "write",
  "date": {
    "kind": "md",
    "month": 6,
    "day": 10
  },
  "start_time": "18:00",
  "end_time": "22:00",
  "memo": ""
}
```

※AI出力では日付情報を構造化して返し、`date_resolver.py` で実際の日付に変換する。

`user_id` とスタッフ名は、原則としてAI出力に含めず、LINEのユーザー情報とスタッフ管理シートから取得する。

---

## 2. シフト変更（shift）

### AI入力例

入力：

```text
10日は20時からです
```

出力例：

```json
{
  "type": "shift",
  "action": "change",
  "date": {
    "kind": "day",
    "day": 10
  },
  "start_time": "20:00"
}
```

変更対象の既存シフトを特定し、指定されていない終了時刻などの情報は勝手に変更しない。

※変更処理が現在の `shift_handler.py` でどこまで実装されているかは、実コードとの照合が必要。

---

## 3. 自由記述を含むシフト登録（shift）

入力：

```text
10日は19時以降ならいつでも大丈夫です
```

出力例：

```json
{
  "type": "shift",
  "action": "write",
  "date": {
    "kind": "day",
    "day": 10
  },
  "start_time": "19:00",
  "end_time": null,
  "memo": "19時以降ならいつでも"
}
```

`end_time` が `null` の場合は終了時刻未指定として扱う。

確定シフトに登録する際の扱いは、運用ルールに従う。

---

## 4. 遅刻連絡（late）

入力：

```text
15分ほど遅れます
```

出力例：

```json
{
  "type": "late",
  "date": null,
  "mode": "delay",
  "delay_minutes": 15,
  "arrival_time": null,
  "reason": ""
}
```

※現在の `late_handler.py` では `mode`、`date`、`arrival_time`、`delay_minutes`、`reason` を扱う。

---

## 5. 欠勤連絡（absence）

入力：

```text
体調不良のため休みます
```

出力例：

```json
{
  "type": "absence",
  "date": null,
  "reason": "体調不良"
}
```

---

## 6. AIが判定できなかった場合（other）

入力：

```text
来週金曜遅めから
```

出力例：

```json
{
  "type": "other",
  "message": "開始時間が特定できません"
}
```

AIが意図や必要な情報を特定できない場合は、推測で補わず確認を求める。

---

## 7. 固定シフト希望（preference）

入力：

```text
毎週火曜日は18時以降なら入れます
```

出力例：

```json
{
  "type": "preference",
  "weekday": "Tuesday",
  "start": "18:00",
  "end": null,
  "available": true,
  "content": "18時以降なら入れます"
}
```

固定曜日や勤務可能時間などの条件を登録する。

---

## 8. 共通ルール

- `type` は `dispatcher.py` の `HANDLERS` に登録された名称に統一する。
- `action` は `EXPECTED_ACTION` に定義された処理内容に合わせる。
- 日付情報はAI解析時に構造化し、`date_resolver.py` で `YYYY-MM-DD` 形式に変換する。
- 時刻は `HH:MM` 形式とする。
- AIが判定できない情報は推測で補わず、確認メッセージで対応する。
- `user_id` とスタッフ名は、LINEの送信者情報・スタッフ管理シートを基に補完する。
- 日付の年が省略された場合は、システムで定めた基準日・対象年月のルールに従って補完する。
- 日付を解決できないタスクは、Spreadsheetへ書き込まない。
- 既存シフトの変更では、指定されていない項目を上書きしない。
